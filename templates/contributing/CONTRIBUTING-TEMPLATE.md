# Contributing Guide

Thank you for your interest in contributing to a VYNTRAX project.

We appreciate every contribution, whether it is a bug report, documentation improvement, feature suggestion or code contribution.

---

# Before You Start

Please make sure you have:

- Read the project README.
- Reviewed existing issues.
- Followed the coding standards.
- Tested your changes.

---

# Branch Naming

Use the official branch strategy.

Examples:

feature/user-authentication

feature/dashboard

fix/sidebar

hotfix/login

---

# Commit Messages

Follow the Conventional Commits specification.

Examples:

feat: add dashboard filters

fix: correct login validation

docs: update installation guide

refactor: simplify API service

test: add unit tests

---

# Pull Requests

Before opening a Pull Request:

- Ensure the project builds successfully.
- Run all available tests.
- Update documentation when necessary.
- Keep Pull Requests focused on a single topic.

---

# Code Quality

Every contribution should:

- Be readable.
- Be documented.
- Avoid duplicated code.
- Follow project standards.
- Include tests whenever applicable.

---

# Respect

Be respectful with all contributors.

Constructive feedback is always encouraged.

---

# Questions

If you have any questions, open a GitHub Discussion or Issue.

---

Thank you for helping improve VYNTRAX projects.
